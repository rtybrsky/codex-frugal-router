# 精簡交接

升級時只傳後續模型完成成果所需的資訊，建議控制在約 150 字內：

```text
目標：<單一可驗收成果>
已知事實：<Luna 已驗證的結果與必要證據>
範圍：<可讀／可寫的精準路徑或資源>
限制：<不可改變的行為、介面或安全邊界>
完成條件：<可觀察結果>
驗證：<要執行的測試、編譯或檢查>
```

不要附完整對話、完整搜尋輸出、無關檔案內容或逐步思考。若日誌很長，只保留第一個有用錯誤、重現指令和必要上下文。

代理回報保持精簡：

```text
狀態：done | partial | blocked
變更：<檔案與結果摘要>
驗證：<命令與 pass/fail>
風險：<無則寫 none>
```

回報不是完成證明；主線程以實際 diff、檔案狀態與命令結果驗收，但不再請另一模型重做內容審查。
