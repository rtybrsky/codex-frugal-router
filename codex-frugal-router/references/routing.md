# 路由與升級規則

只在 Luna 無法可靠完成或任務一開始就明確超過 T1 時升級。不要用任務文字長短判斷；看歧義、影響面、推理耦合、失敗代價與驗證難度。

## T1 — Luna Max

適用於答案或結果可直接觀察、風險低、幾乎不需設計取捨的工作：

- 讀檔、`rg` 搜尋、列檔案、資料盤點、統計與結構化摘要。
- 執行既有測試、編譯、lint、格式檢查或明確的唯讀指令。
- 根據已提供資料回答局部且事實性的問題。

遇到實際程式修改、根因不明的錯誤、跨檔案行為推理或需求歧義時，不要靠增加 Luna 對話輪數硬解，改升級。

## T2 — Terra Max

適用於有明確產品方向、但需要工程判斷的工作：

- 一般功能修改、修 bug、重構、補測試或調整多個相關檔案。
- 局部模組的根因分析、效能改善、相容性修正與測試設計。
- 規格清楚且風險可由測試、編譯器或 diff 直接控制的實作。

若發現必須決定架構邊界、公開 API、資料遷移、安全／權限、不可逆操作，或需求衝突，停止擴大修改並交給 Sol。

## T3 — Sol Medium

適用於需要全局一致性或錯誤成本高的決策：

- 複雜分析、架構或資料模型設計、跨模組根因與長鏈推理。
- 安全、權限、資料遺失風險、遷移策略、公開 API 與重大相容性取捨。
- 成功標準不明、限制互相衝突，或沒有可靠的確定性驗證方法。

Sol 負責必要的分析或決策，不例行重做 Terra 已通過工具驗證的低風險成果。

## 快速判斷

依序問：

1. 是否只是唯讀、統計或執行既有明確檢查？是則 T1。
2. 是否需要修改程式，但範圍與成功標準清楚且可由工具驗證？是則 T2。
3. 是否牽涉架構、跨模組取捨、高風險或無可靠 oracle？是則 T3。

若兩級皆合理，選較低級並設定清楚的停止／升級條件，而不是同時啟動兩個模型。
